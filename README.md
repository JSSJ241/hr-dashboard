# HR Operations Dashboard

Внутренний дашборд для аналитики найма и стоимости HR-процессов.

## Что уже есть

- расчёт внутренней и внешней стоимости найма;
- средняя стоимость на принятый оффер и time to hire;
- сравнение вакансий по полной стоимости;
- аналитика офферов и причин отказов;
- анализ текучести и причин увольнений;
- управление отделами и актуальной численностью для корректного расчёта текучести;
- общий реестр активных сотрудников с фильтрацией по отделам;
- автоматическое уменьшение численности при увольнении и увеличение при найме;
- помесячная динамика расходов;
- план-факт стратегических HR-метрик;
- месячные KPI;
- редактирование данных и экспорт CSV.

## Структура

Проект состоит из двух связанных страниц:

- `index.html` — стоимость найма, вакансии и HR-метрики;
- `turnover.html` — текучесть, причины увольнений и отделы риска;
- `supabase/turnover_schema.sql` — таблицы `departments` и `terminations`;
- `supabase/employee_roster.sql` — реестр сотрудников и автоматическая синхронизация численности;
- данных хранятся в Supabase;
- графики строятся через Chart.js.

## Локальный запуск

```powershell
python -m http.server 4174
```

Затем откройте `http://127.0.0.1:4174/`.

Перед использованием раздела текучести выполните `supabase/turnover_schema.sql`
и затем `supabase/employee_roster.sql` в SQL Editor проекта Supabase.

После создания таблиц откройте `turnover.html` и нажмите **«Сотрудники»**.
Численность отделов рассчитывается автоматически по активным сотрудникам.
Увольнение уменьшает численность отдела, а добавление сотрудника — увеличивает.

## Публикация

Сайт публикуется из ветки `main` через GitHub Pages.

## Важно про безопасность

Текущая проверка пароля выполняется на стороне браузера и не является полноценной
аутентификацией. Доступ к данным должен дополнительно ограничиваться политиками
Supabase Row Level Security. Для рабочего HR-контура с зарплатами, именами
сотрудников и кадровыми решениями рекомендуется перейти на Supabase Auth или
другой серверный механизм авторизации.

Политики из `turnover_schema.sql` сейчас разрешают чтение и запись для `anon`,
чтобы новый раздел заработал без дополнительной настройки. Это допустимо только
для тестовых данных. Перед загрузкой реальных кадровых данных нужно включить
Supabase Auth и заменить эти политики доступом только для `authenticated`.
